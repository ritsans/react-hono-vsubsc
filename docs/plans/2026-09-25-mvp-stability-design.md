# MVP 安定化の設計

## 目的

ログインユーザーの切り替え、通信遅延・失敗、連打、登録情報の変更が起きても、別ユーザーの情報や古い集計を表示せず、操作の成否を利用者が判断できるようにする。

## 方針

現状の画面構成と直接の API 呼び出しを維持する。新しいデータ取得ライブラリは導入しない。セッションのユーザー ID が変わると一覧画面を作り直し、取得処理は最後に開始したものだけ画面に反映する。登録・削除・円換算中は重複する操作を止め、一覧を変更した時点で以前の円換算結果を消す。通信に失敗した場合は画面に知らせ、一覧は再試行できるようにする。

API はデータベースに保存できる金額と実在する請求日だけを受け付け、入力の誤りは保存処理より前に拒否する。成功と失敗の境界をテストで確認し、失敗を成功と見なすテストは修正する。

## 確認方法

ユーザー切り替え、遅延した応答、連打、通信失敗、契約変更後の集計、入力不正を再現するテストを追加する。既存テスト、lint、型チェック、ビルド、Worker の dry-run も通す。
