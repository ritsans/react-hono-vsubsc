# データベースの説明書

作成日: 2026-09-18

このアプリがデータを保存している「表（テーブル）」を5つ、それぞれ何のためにあるかを説明する。
**正確な項目名や型は `src/server/db/schema.ts` というファイルが正しい情報源。

## 表（テーブル）は全部で5つ

5つのうち4つ（`user`・`session`・`account`・`verification`）は、ログイン機能を提供している外部の部品（Better Auth）が自動的に管理している表。残り1つの `subscription` だけが、このアプリ独自の「登録したサブスク情報」を保存する表。

イメージとしてはこうなっている。

```
利用者（user）
 ├─ ログイン中の記録（session）
 ├─ ログイン用のパスワード（account）
 └─ 登録したサブスク（subscription）

パスワード再設定などの一時的な確認コード（verification）は利用者と直接は紐づかない
```

利用者を1人削除すると、その人のログイン記録・パスワード・登録したサブスクは自動的にすべて一緒に消える。データベース自体がそう約束してくれているよう定義しているので、消し忘れは起きない。

## userテーブル（利用者）

会員登録した人の情報。名前・メールアドレス・プロフィール画像欄などが入る。

- メールアドレスは重複登録できないようになっている。ログイン時のIDとして使うため。
- パスワードそのものはこの表には入っていない（次の `account` に別で保存する）。
- プロフィール画像欄はこのアプリでは使わないが、空のままにできる形で用意している。Better Authが「この欄がある前提」で作られていて、無いとエラーになってしまうため。

## sessionテーブル（ログイン中の記録）

「今どのブラウザがログインしているか」を記録する表。ログインするたびに1件増え、ログアウトしたり時間が経ちすぎたりすると無効になる。使い捨て。

## accountテーブル（ログイン方法）

パスワードのハッシュ値（そのまま読めない形に変換した値）を保存する表。将来「Googleでログイン」のような別の方法を足せるように、`user` とは別の表になっている。今はメールアドレス＋パスワードの方法しか使っていない。

## verificationテーブル（確認コードの一時置き場）

メールアドレスの確認やパスワード再設定に使う、使い捨てのコードを一時的に置いておく表。

## subscriptionテーブル（登録したサブスク）

利用者が「このサービスに契約している」と登録した情報。このアプリの主役となる表。

- サービス名（例: Netflix）
- 金額と通貨（円かドルか）
- 支払いの周期（月払いか年払いか）
- 次回の支払日
- 参考URLやメモ（任意）

一番大事な約束事は、**どのサブスク情報にも、必ず「誰が登録したか」がセットで記録される**こと。持ち主のいないサブスク情報はデータベースの仕組み自体が作れないようにブロックしている。これにより、後からログイン機能を作り足す途中で確認漏れがあっても、「他人が登録したサブスクが見えてしまう」事故をデータベース側で防げる。

## この表を触ってよいプログラムを1か所に絞っている

`subscription` の情報を読み書きするプログラムは、`src/server/db/subscriptions.ts` という1つのファイルだけに集めている。ここを通る処理は必ず「誰の情報か」を指定しないと動かない作りになっており、指定し忘れがあればプログラムを組み立てる段階でエラーとして検知できる。詳しい経緯は `.claude/plans/services-crud-userid.md` を参照。
